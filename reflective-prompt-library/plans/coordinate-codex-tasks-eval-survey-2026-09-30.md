### Scalar-Only Validation Selection

The same disposable command searched 256 no-signal binary classifiers. Selection received only scalar validation scores; it did not read labels/cases. It selected candidate 94 on 64 validation cases, then generated 4,096 independent final cases and scored baseline/winner. Nominal true accuracy was 0.5 by the no-signal construction, not a measured agent property.

| Measurement | Baseline candidate 0 | Selected candidate 94 | Winner minus baseline |
| --- | --- | --- | --- |
| Validation accuracy | 0.5625 | 0.671875 | +0.109375 |
| Untouched final accuracy | 0.49755859375 | 0.478759765625 | -0.018798828125 |

Reproduction parameters: Python `random.Random`, label seeds 271828 (validation) and 314159 (final); candidate prediction seeds `10000 + candidate_id` and `90000 + candidate_id`; candidate IDs 0–255; strict score increase keeps a new incumbent. Final labels are generated only after selection. The throwaway script is not installed as a new benchmark or runner.

In this session-scoped single-seed draw, the validation gain did not transfer. All candidates have true accuracy 0.5 under the construction; the negative final delta is sampling noise, not evidence that the selected candidate truly degraded. Maximizing scores across 256 candidates creates selection optimism, and the baseline's 0.5625 validation score is itself a noisy draw. The scalar-only selection computation does not depend on macOS, but only this host/session run was observed; it is not an agent benchmark, a mean over seeds, or evidence of provider performance.

- Grader repair changes the yardstick: version it, use the appropriate out-of-band owner decision, re-grade comparable outputs, and rebaseline/restart when the ordering or significance no longer holds. An optimizer cannot self-authorize an authoritative-oracle edit.
- Hidden inputs can leak through disk, transcripts, traces, tools, or network copies. The probe establishes one process/path boundary only; a real host must demonstrate the relevant exposure paths.
- Pausing observation is not cancellation or effect rollback. Hosted evaluation may call live tools before candidate deployment; effect authority and isolated endpoints remain separate requirements.
- No provider API benchmark, installation, production approval, actual Codex scheduling, or new routing/skill behavior is claimed.
- Acceptance criteria 1–5 are satisfied: source pins/refutations map to the State Ledger, authority/adoption boundaries to the local mapping and ECT-1–ECT-8, and execution/closure to the package/access/selection results and repository gate above. This is evidence for the scoped survey, not installed-agent efficacy.
- A future runnable pilot needs a named local task, approved/isolated eval, objective/budget, bounded optimization, untouched baseline/winner final comparison, and independent host wake/pause/recovery evidence only if cross-Task monitoring is required.
