## Prompt & Memory Architecture

### The Seven-Category Audit Vocabulary and the Procedure Layer
The cited rethink uses the user-supplied seven-item list as an audit vocabulary for an already contract-shaped library. Its exact provenance and exhaustive usefulness are unverified; no taxonomy or wording was newly adopted:
1. Requirements (Triggers, usage-first inputs)
2. Output Contracts (Schemas, artifacts, dual-payload splits)
3. Invariants (Negative constraints, safety floors, Never blocks)
4. Validation (Second-method verification, decorrelated checks)
5. Transformation (Spec-to-implementation, SOP compilation)
6. Knowledge (Project context, glossary, reference docs)
7. Observation (Execution feedback, tool return consumption)

**Procedure Layer:** The cited record rejects unsupported exclusivity and retains reasoning scaffolds, skill sequencing and recipes for model direction and human auditability. It does not prove that every procedure improves model performance.

### Context Hygiene and Memory Substrates
- **File-Artifact Memory:** Canonical spec, packet and ledger files provide inspectable continuation state outside the transcript; persistence does not guarantee fidelity, freshness or freedom from hallucination.
- **Handoff Recovery:** `reflective-handoff-retro` already requires rebuilding continuation state from canonical artifacts and checking packet fidelity. PC-02 below proposes an additional explicit non-goal reassertion, not a new recovery mechanism.
- **Human Cognition Guidance:** HCC-1 supports the human learner's voluntary diagnostics/practice/agency; HCC-2 specifies scientific-source/read/design/population bounds; HCC-3 distinguishes performance, confidence and calibration constructs. These are guidance/compatibility checks, not measured human benefit or AI acquisition of psychological mechanisms ([owner](human-cognition-adoption-2026-10-02.md#candidate-adoption-ledger)).
