## Socratic Questions and Disposition (the surveyed text)

1. **Is the headline rule followable?** §4 sets a per-call character target while conceding measurement only "where the tools permit it" and that a Markdown instruction cannot intercept tool output. In the default case (no projection layer) the only residual action is "ask for less", which the same section already states as locate-then-read. Disposition: the target is an instruction without an observable; its number adds nothing over the hygiene and invites a later reader to cite it as an established limit its own README disclaims. Recorded; nothing adopted.
2. **Is the efficiency thesis falsifiable?** The profile forbids over-claiming (no savings percentage, no token conversion, "a stopped task is not evidence of efficiency") but commits to no threshold or effect direction, and its "installed vs observed in use" clause absorbs any null result. Four lenses independently ruled the thesis **unfalsifiable as stated**: honest as a code of conduct, empty as a claim. Its "Try it responsibly" protocol is under-specified in ten named places (no sample size; "matched" undefined; no method to separate compaction or caching; no observation method for "actually observed in use"; no blinding or order control; no primary endpoint; the instrument's own ~8,243-character context cost never netted out; character→token mapping unmeasured). Disposition: study value only; this is why the survey clears no adoption bar — the artifact structurally cannot supply an observed occurrence.
3. **Which unit does the number bound?** The README calls 12,000 a "response target"; the rules bind the same number to "the complete serialized text emitted by one combined tool call" — an input, not an answer. The two framings license opposite behavior at the boundary. Recorded as an internal inconsistency.
4. **Does "reuse previously read ranges" license the I-1 failure?** §3 ("within the same context and source version, reuse previously read ranges; reread only changed content") and §5 ("project an already retained result … do not fetch the entire object again") exert anti-re-fetch pressure with no counterpart to I-1's oracle outside the writer's channel. After a write, the file *is* changed content, yet the retained result is the writer's own channel. §7's "identical command text alone never proves a rerun unnecessary" pulls the other way for checks but not for reads. Disposition: **rejected as a hazard**, not filed as out of scope — a session following the profile could skip the post-write comparison in the name of not re-reading.
5. **What audits the merge?** The install path merges the profile into `AGENTS.md` and then asks a fresh task to "identify the effective instruction source" — a self-report that the merged profile can itself answer. No pin, hash, tag, or signed release; updates are manual replacement of the whole section. What the README does right: back up first, replace rather than append, remove only its own section, manual updates. Disposition: `deploy` blocked; the practice, not this text, is the risk.
6. **Does the artifact pass its own honesty test?** By §8's own gate a single unsigned commit with no usage evidence is "installed", not "observed in use". Recorded without irony: the README says as much.

4. **Label.** "Host-hygiene profile" → "scaffold fragment offered as an authority-file merge" (methodology lens; `METHODOLOGY_MAP.md` scaffold/harness/skills distinction).
5. **A lens reported a live tool divergence that did not happen.** The usability lens stated that a `:raw` read of `reflective-dispatch/SKILL.md:155-162` "dropped words" relative to the anchored read — offered as a live preview-versus-source instance. The coordinator extracted both tool results from that lens's transcript and diffed them: byte-identical (225 and 419 characters on the two cited lines; the anchored view merely carried elision markers for lines outside the range). This was a **lens misreport about a tool, not a tool misreport**; I-1's trigger ("a second tool misreport in any record") did **not** fire. 7. **The README's "community project, not an official … product" sentence** is coordinator-observed from the fetched README (2026-09-10), not embedded in the packet's verbatim excerpts; tiered accordingly.
