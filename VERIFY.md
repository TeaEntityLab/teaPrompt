## What this repo is

A Markdown prompt/skill library plus a Python governance gate suite. There is
no server and no build artifact: the "product" is the prompt corpus and its
validators. Verification = running the gate suite and checking registry
invariants.

## Launch

```bash
cd "$(git rev-parse --show-toplevel)"   # repo root; all commands run from here
make all                                # full gate: pytest + 8 validator scripts + 3 route evals
```

Expected: exit 0. Total wall time ~15–30 s.

## Doctor (fast smoke, ~2 s)

```bash
python3 reflective-prompt-library/plans/validate_links.py        # expect: "All validations passed!"
python3 reflective-prompt-library/plans/validate_governance.py   # expect: "valid governance metadata"
```

If doctor fails, stop: the repo is unhealthy and a full sweep wastes time.

## Environment quirks (verbatim)

- `route_paraphrase_eval.py` writes `plans/route-00X-results.json` on every
  run. These files are gitignored and never appear in `git status`.
- `lint_skills.py` exits 0 with **one known non-blocking warning**:
  `agent-governance-scaffold/SKILL.md` exceeds the 20k-char body threshold
  (accepted per the 2026-07-18 panels, ledgered as R10). Do not classify this
  as a failure.
- `make validate` runs the route evals; `make test` runs pytest. `make all`
  runs both.
- Python 3 only; no virtualenv required (stdlib + pytest).

## Failure classification

| Class | Meaning | Repair |
| --- | --- | --- |
| Product regression | Repo behavior changed for the worse (validator fails, test fails, registry cardinality changed) | Report; never edit map/spec/tests to match |
| Doc drift | This map no longer matches a healthy repo | Update the doc |
| Spec/oracle error | `acceptance.yaml` expectation is wrong | Spec is read-only by convention; propose change for human review |
| Harness failure | Python/pytest/toolchain broke, not the repo | Fix the harness |
